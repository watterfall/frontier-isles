# 岛屿探索 v5 · 空间入口、研究房间与可接续的探索

## 方向与范围
延续现有矿物纸张海图。此次改造已有岛屿体验，不替换产品身份。模式为 Experience → Read → Operate：先辨认研究空间，再阅读材料，最后形成自己的下一步。没有积分、完成率、强制顺序或访问解锁。

首屏仍以岛屿为主；岛内导航给出稳定空间位置和可选探索线索。点击建筑先靠近并看见内部结构，不立即打断地图观察。入口可以直接进入任一有材料的房间；已经读过的房间可接续。阅读时保留建筑身份和返回路径。签名交互是“靠近建筑—展开研究平面—进入房间—带着问题去下一处”；相机采用已有指数缓出，纸面展开使用短暂裁切，减少动态模式禁用过渡。

## 交互合同
1. 海图 → 岛屿：保留原有海图观察点。岛内总览提供共享地形和建筑坐标的小图、用途筛选、可选导览线索。
2. 岛屿 → 建筑入口：画面聚焦真实地址；显示建筑独有的研究结构、实际房间和材料预览。阅读是显式动作，拖动只改变视角。
3. 建筑 → 房间：问题墙按问题展开；文献阁可选两份真实材料对照；白板厅围绕竞争解释；实验坊可写预测、推翻条件与下一次检验。房间由已有材料生成，不编造空房间或研究证据。
4. 房间 → 下一步：选中的问题随行；研究草稿追加到现有私人札记；提供与当前任务有关的下一处。返回上一处恢复房间与阅读位置，返回入口恢复建筑定位。
5. 开放探索：导览是建议，所有建筑始终可自由进入；路线仅表示阅读顺序，不表示科学因果或已验证跨域关系。

## 模块边界
- `explorationNavigation`：地址、历史、返回与房间选择，不依赖绘图。
- `buildingExploration`：由现有内容投影房间结构、对照材料与导览意图，保留来源。
- `IslandWayfinder`：小图与可选路线，读取与场景同一套地址。
- `BuildingPlan`：可访问的研究结构图，入口和阅读视图复用同一房间。
- `ResearchDesk`：文献对照与最小检验草稿，追加现有私人札记。

这些模块是对当前用途的抽提，不创建通用游戏引擎。AI 后续可提出带有出处与理由的候选探索路线，使用相同地址与材料对象；用户选择、草稿和验证状态仍分开。此轮不伪装模型调用，也不把阅读记录当成科学成果。

## 已实现的返回与草稿边界
入口预览不创建阅读历史。显式进入房间才记录 UI 地址；历史最多 30 处，返回后转向新房间会从当前位置分叉。回到岛上保留所选建筑；回到上一处保留房间及可恢复的滚动位置。问题笺展开、文献选择与研究工具展开/输入状态在当前岛屿停留期间保留；切换岛屿会清理临时状态。只有显式追加到已有私人札记的文字才沿用浏览器持久保存与导出。超出 1200 字符时保留草稿和原札记，要求整理后再追加。

## 后续内容扩展方法
| 扩展内容 | 所在模块 | 必须保留的约束 |
| --- | --- | --- |
| 新的已收录研究材料 | `islandDepth.ts` 的内容投影 | 使用稳定房间地址，保留原始来源和编辑性质；结构图、房间与历史共同读取它 |
| 建筑的研究用途与入口语义 | `buildingExploration.ts` | 房间随实际材料出现；几何形状不暗示真实物理楼层或研究成熟度 |
| 新的私人工具 | `ResearchDesk.tsx` | 明确输入、用户判断与来源；返回时保留草稿；追加札记不覆盖原文 |
| 新的导览线索 | `EXPLORATION_ROUTES` / `IslandWayfinder` | 只引用可到达的建筑地址；允许自由偏离路线，解释路线含义 |
| 导航方式或渲染器 | `explorationNavigation.ts` / `BuildingPlan.tsx` | 不在绘图层另存一套导航状态，不把访问转成账本成果 |

AI 生成候选路线或检验建议可以接入这些稳定地址与来源对象。当前实现提供相应组织边界，尚未增加新的模型执行、实验编排或自动科研闭环。
