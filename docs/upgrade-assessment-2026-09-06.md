# 问题群岛：项目评估与探索体验升级

> 本文保留第一轮评估记录。用户校正后的第二轮已经移除分步表单和实践印记，改为自由追问、可选 AI 协作与问题群岛航迹；当前实现与验证见[第二轮迭代报告](upgrade-v2-2026-09-06.md)。

评估日期：2026-09-06。范围：当前 checkout 的产品设计、科学语义、MCP 接入、交互、数据治理和本地验证。本文记录一轮实际实现；不代表部署或科研有效性证明。

## 判断

项目最有价值的部分是“研究状态成为可探索的空间”：问题岛、研究建筑、跨岛关系、日夜探索和不可覆写的事件账本已经形成一致的体系。瓶颈在于从一个引人入胜的关联走到一份可检查的研究记录，中间缺少足够直接的入口和连续体验。继续堆叠岛屿、面板或奖励数值，很难弥补这个缺口。

本轮把既有“领域碰撞”入口升级为完整的个人探索过程，复用海图的视觉语言与数据边界。主要产品假设是：科学探索者需要可发现的跨域线索、可表达的竞争解释，以及能保留失败和不确定性的研究记录。尚未做用户研究，不能声称这个假设已被验证。

## MCP 实测与科学边界

通过实际工具调用、公网 JSON-RPC 握手以及新服务路由读取验证：

- 服务：`https://xfrontier.science/mcp`；`xfrontier 0.9.0`；协议 `2025-06-18`；本轮数据版本 `xf-e3e450f3fa16`。
- 当前上游：1,950 条记录、55 个 cluster、38 个数学结构；问题层为 55 个 great questions、42 条 authored collisions。
- 上游 collision 的两端是问题 ID（GQ），不是记录 ID（XF）；本轮没有捏造两层之间的对应关系。
- `nearest(space=topical)` 与 `evaluative` 的语义不同。新版未把评分空间相似度称作学科联系，也未把上述 42 条编辑关系称作算法发现。
- 问题出处只证明问题被提出。出处链接在需要时通过 `get_question` 查询，版本与 ID 必须一致；无法核对时明确报告。
- 公共 HTTP 会话不提供写工具。新增 API 只调用固定读取方法，不暴露通用 MCP 代理；本轮没有上游账本写入。

运行时路径：

```text
用户打开领域碰撞
  → 立即显示带日期与版本的随包快照
  → GET /api/xfrontier/catalog
  → initialize → tools/list → resources/read + search_questions
  → 验证完整页、同版本、开放问题边界与完整关系端点
  → 已连接 / 上次连接资料 / 离线资料

开始探索
  → 固定该问题对及来源版本
  → 本机草稿 + 派生步骤进度
  → Markdown 记录 / JSON 备份
```

目录缓存 5 分钟，并发刷新共享一份请求，失败后有 30 秒冷却期。有旧运行时缓存则标为 stale；没有则返回 503，让前端明确使用随包版本。网络晚到不会改写已经开始的探索。

## 旧图集漂移

独立运行 `node --experimental-strip-types packages/data/scripts/sync-xfrontier.mjs --check` 检查原有图集引用：

- 683 个引用：682 active，1 withdrawn，0 unknown。
- 旧快照 `xf-6eb361265784 / MCP 0.6.0`，当前 `xf-e3e450f3fa16 / MCP 0.9.0`。
- 多个引用的内容哈希发生变化。已有失效来源仍保留其撤回状态。

本轮保持原有图集的审核基线。新的问题目录使用独立、可复现的投影；这两个版本不能被一句“数据已全部更新”合并。后续应该按差异审阅来源内容、结构映射与依赖，再刷新旧基线。

## 使用与维护

桌面海图顶部选择“领域碰撞”；手机选择“开启一次领域碰撞”。目录可搜索，选择问题对后开始探索。步骤可自由回看；前进按钮检查当前步骤是否已记录必要内容。任何结果都可以被修改，印记从现有记录实时计算。

核对或显式刷新随包问题目录：

```sh
node --experimental-strip-types scripts/sync-exploration-catalog.mjs --check
node --experimental-strip-types scripts/sync-exploration-catalog.mjs --write
```

脚本只读取公共 MCP，写入本项目的独立问题快照；不改原有图集、研究映射或上游内容。

本地隔离开发可设置 `FI_API_TARGET=http://127.0.0.1:8788` 并将 Vite 放到 5174。Playwright 支持 `FI_E2E_WEB_PORT` / `FI_E2E_API_PORT`，默认端口保持原值。

## 下一轮优先级

1. **验证研究质量提升。** 邀请 5–8 位目标用户完成同一任务，比较旧入口和新版产出的具体问题、竞争解释、可区分预测、失败条件；研究者盲评，点击数只做诊断。
2. **审阅旧图集来源漂移。** 从变化引用出发检查相关结构映射与科学叙述，不做纯元数据刷新。
3. **把探索接入既有模型与证据链。** 明确选择一个适用模型，把运行参数、结果和限制作为一条可追溯证据加入探索；仍由用户决定是否提出正式研究记录。
4. **检验迁移，而非累积相似性。** 在未来任意领域组合功能中，要求显式变量对应、适用条件、替代机制和区分实验，再考虑生成辅助。
5. **统一个人研究记录。** 验证需求后再接通航行笔记、模型回执和碰撞记录的恢复、导入与跨设备存储；不提前引入账户依赖。
